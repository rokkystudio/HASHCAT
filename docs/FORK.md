# Статус репозитория: форк

Этот репозиторий — **самостоятельный форк hashcat**, а не зеркало upstream.
`source/` — наш рабочий код. Синхронизация с `github.com/hashcat/hashcat`
отключена: обновления из upstream не применяются автоматически и не являются
целью.

Причины:

* upstream развивается медленно, а наши требования (Android, Vulkan, драйвер
  Adreno) в него не входят;
* часть режимов на мобильных GPU не работает без локальных правок, которые
  upstream не примет;
* ручное слияние сотен файлов при каждом релизе дороже, чем сопровождение
  собственного набора патчей.

## Что это меняет на практике

1. `scripts/UPDATE.ps1` больше не «обновляет» — он проверяет целостность
   локального дерева и показывает метаданные сборки. Никаких `git pull`
   из upstream нет и не планируется.
2. Любое изменение `source/` — это патч форка. Он должен быть описан в реестре
   ниже, проверен на устройстве и покрыт регресс-гейтом
   (`tools/check-opencl-regression.ps1`).
3. Версия hashcat (`v7.1.2`) остаётся базовой точкой отсчёта upstream. Ревизия
   форка указывается отдельно в реестре и в сообщении коммита.
4. При переносе кода из upstream (если понадобится) переносится конкретный
   патч, а не весь релиз, и он проходит те же проверки.

## Реестр патчей

| # | Патч | Файлы | Причина | Риск |
|---|---|---|---|---|
| P1 | `--backend-info-json`: машинно-читаемое описание backend'ов и устройств | `src/backend_info_json.c`, `src/main.c`, `src/user_options.c`, `src/usage.c`, `include/types.h`, `src/Makefile` | Приложению нужен стабильный контракт вместо парсинга `-I` | Низкий: только чтение, отдельная ветка вывода |
| P2 | `--backend-ignore-vulkan`: пятый флаг исключения backend'а | `src/user_options.c`, `src/usage.c`, `include/types.h`, `src/backend.c` | Явный выбор backend'а в приложении, без неявного отката | Низкий: аддитивно, поведение OpenCL не меняется |
| P3 | Adreno: предпочтение optimized-ядра | `src/interface.c` | Компилятор Adreno не линкует pure-ядра ряда режимов (`CL_OUT_OF_HOST_MEMORY`), optimized-вариант того же режима собирается и работает | Средний: optimized-ядро ограничивает длину пароля (для режима 0 — 0–31 байт); отключается переменной `HASHCAT_DISABLE_ADRENO_OPTIMIZED=1` |

### P3 подробнее

Проверено на RedMagic 7S Pro (Adreno 730, Android 13), сборка arm64:

```text
m0 -a 0, pure:      clLinkProgram(): CL_OUT_OF_HOST_MEMORY -> build failed
m0 -a 0, optimized: Status: Cracked, 1316 H/s, Kernel.Feature: Optimized Kernel (0-31 bytes)
m22000 -a 0:        работает без изменений (optimized-варианта у режима нет)
```

Патч не переписывает ядра: он выбирает существующий optimized-вариант там, где
он есть, и оставляет pure-ядро для режимов без optimized-варианта (существующая
ветка fallback в `hashconfig_init`). Для режимов без optimized-ядра поведение
не меняется.

Проверки, обязательные при изменении P3:

1. `hashcat -I` на устройстве — список устройств не изменился;
2. `-m 0 -a 0` без `-O` — находит пароль, в логе строка про optimized-ядро;
3. `HASHCAT_DISABLE_ADRENO_OPTIMIZED=1` — воспроизводит исходную ошибку
   (то есть отключение работает);
4. `-m 22000 -a 0` — работает как раньше;
5. регресс-гейт OpenCL зелёный.

## Чего в форке нет

* автоматического слияния с upstream и его тестов;
* поддержки CUDA/HIP/Metal сверх того, что было в базовой версии;
* гарантий совместимости с upstream-модулями, собранными отдельно.
